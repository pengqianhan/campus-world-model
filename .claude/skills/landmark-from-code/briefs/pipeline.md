# Brief: pipeline agent

<!-- Sent as-is to the pipeline agent at the start of round 1 (Clock Tower, 2026-10-20), with local paths rewritten for `landmarks/clocktower/`. Model: the lead's (Claude Opus); agent type: general-purpose. -->

You are the **pipeline** agent on a small team building the University of Auckland Clock Tower in three.js from code alone, checked against Street View photographs. Project folder: `landmarks/clocktower/` in this repository; paths below are relative to it (do not commit — the lead commits). Other agents (tower, centre, facade, look) are editing `src/` at the same time; you own `tools/`, `run.sh`, `README.md`, `data/` and a new `config/`.

**Read first:** `docs/CONTRACT.md` (ownership, frame, running things, budget, rules) and `docs/ART_BIBLE.md`. Then look at `tools/` (`shot.mjs`, `compare.mjs`, `strip.py`, `streetview_collect.py`), `refs/streetview/views.json`, `refs/camera.json`, `tools_solve_camera.py`.

**Goal: make this a reproducible pipeline** — someone with a fresh clone (plus a Google Maps key in `~/.gmaps_key` and a Python with `requirements.txt`) runs one command and gets the data, references, renders, comparisons and metrics. Today several steps only exist as one-off scripts. Do this:

1. **Data stage** (`tools/data/`): turn the one-off scripts into pipeline scripts with outputs under `data/` (gitignored if large):
   - fetching the 8 LINZ 2024 LiDAR tiles (public, no login) from `https://opentopography.s3.sdsc.edu/pc-bulk/NZ24_Auckland/CL2_BA32_2024_1000_{3603,3604,3605,3606,3703,3704,3705,3706}.laz` — skip files already present; tiles already downloaded elsewhere may be symlinked rather than re-downloaded;
   - measuring the building: the lead's one-off scripts `ct_measure.py`, `ct_frame.py`, `ct_heightmap.py` (read them; they became `tools/data/`). They produce `clocktower_pts.npy`, `clocktower_ring.json`, `clocktower_frame.json`, `clocktower_plan_frame.png`, `clocktower_front_elevation.png`, `clocktower_heightmap_vs_aerial.jpg`. Reproduce the same outputs in `data/`. The campus outline in the main project's `campus.json` is offset from the LiDAR by several metres; the frame must come from the LiDAR (as `ct_frame.py` does), not from `campus.json`.
   - Put building-specific settings (building id, origin, LiDAR tile list, ground height, frame) in `config/clocktower.json` so the same pipeline can later run for another building.
2. **References stage**: `tools/streetview_collect.py` already caches tiles under `refs/streetview/tiles/`. Make it read the config and keep it cache-first. **Do not fetch any new Street View tiles** (they are billed): keep the panorama count at 12; a rerun must download 0 new tiles (createSession/panoIds/metadata calls are fine). Add a `--offline` mode that rebuilds the views from the cached tiles and a saved metadata file without any network call, and save the metadata so that works.
3. **Camera refinement** (`tools/refine_cameras.py` or `.mjs`): Street View positions are good to about 1–3 m and the views do not yet overlap the model exactly. For each panorama (its three views share one camera), search a small correction (position ±3 m, height ±1 m, yaw/pitch ±2°) that best overlaps the model's silhouette with the photograph's building/sky boundary. Render the model's silhouette yourself in a separate page you own (e.g. `tools/mask.html` importing `src/clocktower.js` directly with flat white materials on black — do not edit `src/main.js`, which the look agent owns). Segment sky in the photographs by colour (it is clear blue; trees, people and cars are not building — use the upper part of the building and the tower against the sky, which is robust). Write `refs/streetview/views_refined.json`; make `tools/compare.mjs` use it when present (keep its command line the same). Report the corrections found and the overlap (IoU) before/after.
4. **Metrics** (`tools/metrics.py`): per view, silhouette IoU, and luminance percentiles p02/p10/p50/p90/p98 and mean colour of the reference vs the render inside the building region; a summary table (markdown) and `metrics.json` in the compare output folder. Hook it into `compare.mjs` after the strips (an option to skip it).
5. **`run.sh`** with stages (`data`, `refs`, `refine`, `compare`, `metrics`, `all`), each idempotent, and **`README.md`**: what the pipeline does, the frame, each stage's inputs/outputs, how to run, what is billed and how much (Map Tiles API Street View tiles: 100,000 free a month, then $2 per 1,000; metadata free), licences (LINZ LiDAR and aerial CC BY 4.0; Street View imagery is Google's — used as references only, never published or traced), and how to point it at another building.

Verify each stage by running it. `compare.mjs` and the page need the local server (`http://localhost:8765`, see the contract). The GPU is shared — don't render more than you need. Run Python with the `-I` flag and add packages there only if needed (say which). Finish with a short report: files, commands, what each stage outputs, the refinement results (per panorama correction and IoU before/after), anything that does not reproduce, and anything the other agents should know.
